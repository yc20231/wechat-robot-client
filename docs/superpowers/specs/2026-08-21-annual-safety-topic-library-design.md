# 阳强塑料工厂 365 天安全主题库设计

## 1. 目标

将当前服务器使用的 25 条常规安全主题扩展为 365 条，形成固定、全年均匀轮换的每日安全提醒内容库。

主题库只覆盖阳强塑料工厂实际存在的设备、区域和作业，不接入天气，不按月份或节假日调整，也不加入质量、环保或现场不存在的通用工业作业。每天继续发布一个主题、三条提醒和一句标语。

“全年不重复”定义为：

- 365 个每日主题标题唯一；
- 每条完整文案唯一，任意两条不得出现相同的三项提醒组合；
- 同一项重要安全原则可以在不同设备、作业阶段或异常场景中再次强化；
- 不允许仅通过替换同义词制造表面不同的主题。

365 天轮换完成后，从第一条开始下一轮。

## 2. 内容边界

主题只覆盖以下已确认的现场范围：

- 吹膜机、制袋机、造粒机；
- 上料、牵引、收卷、换卷、破碎和清料；
- 原料库、成品库和边角料存放区；
- 叉车、装卸和厂内车辆；
- 配电、压缩空气和设备检修；
- 消防、疏散和个人防护；
- 交接班、现场整理和应急处置。

不得为凑足数量加入现场不存在的吊装、危化品、有限空间等内容。若今后现场新增设备或作业，应先更新范围清单，再扩充主题源库。

## 3. 内容体系

365 条内容按完整安全体系组织，并以现场相关性为首要原则。目标配额如下：

| 安全类别 | 目标数量 |
| --- | ---: |
| 生产设备与操作 | 105 |
| 消防与用电 | 45 |
| 仓储与物流 | 45 |
| 检修与能源隔离 | 40 |
| 个人防护与职业健康 | 35 |
| 现场环境与秩序 | 35 |
| 应急处置与班组管理 | 35 |
| 其他现场实际风险 | 25 |
| 合计 | 365 |

每条主题通过四层结构定义：

`安全类别 -> 现场对象 -> 作业阶段 -> 具体风险`

例如“吹膜机操作”不再只对应一条宽泛提醒，而是分别覆盖开机检查、引膜、正常运行、断膜处理、换规格、清理和交接等不同场景。

## 4. 文案规范

最终运行条目继续兼容现有格式：

```json
{
  "focus": "吹膜机断膜处理",
  "points": [
    "发现断膜先停机，确认辊筒停止转动",
    "缠膜使用工具清理，手不要伸入辊隙",
    "重新引膜时采用点动低速运行"
  ],
  "slogan": "断膜先停机，处理不冒险"
}
```

文案采用“现场规范用语”：员工能够直接理解，同时保持企业安全提醒应有的准确和正式。

具体规则：

- 标题描述明确的对象或场景，避免只有“注意安全”一类空泛表达；
- 三条提醒分别提供可执行动作，不凑相同字数，不强制统一句式；
- 内容长短按实际信息自然变化，但必须适配现有海报；
- 标语总结当天核心风险，避免口号化、押韵化或夸张表达；
- 重要原则允许跨场景出现，但对象、阶段、风险和处置动作应有实质差异；
- 不使用员工难以理解的法规摘录或过度口语化表达。

## 5. 编排规则

主题采用固定 365 天循环，不读取天气、月份或节假日。生成阶段先完成风险矩阵，再进行确定性的交叉编排，避免相近内容集中出现。

编排约束：

- 相同安全大类至少间隔 3 天；
- 相同设备或区域至少间隔 7 天；
- 消防、用电、叉车和机械伤害等高频风险均匀分布全年；
- 应急、交接和班组管理等管理类内容不得连续发布；
- 连续两天避免强调相同核心动作，例如连续出现“断电挂牌”；
- 编排结果必须稳定可复现，重新生成不能随机改变已有日期对应关系。

如全部硬约束在边界位置无法同时满足，生成器应报告冲突而不是静默降低标准。调整内容配额或排列规则后重新生成。

## 6. 数据与生成流程

建立一份结构化源库作为唯一事实来源。每条源记录除最终文案外，还保存以下维护标签：

- `category`：安全类别；
- `object`：设备、区域或作业对象；
- `stage`：开机前、运行中、异常、清理、检修、交接等阶段；
- `risk`：当天聚焦的具体风险；
- `action_keys`：主要动作标签，用于相邻内容检查。

生成器读取源库、验证内容并执行固定编排，然后同时生成：

- `pkg/templates/safetyreminder/topics.json`，作为项目内置主题库；
- `.deploy/safety-reminder-topics-plastics.json`，作为部署主题库；
- 一份带序号和分类信息的 365 天审阅清单。

两份运行 JSON 必须由同一次生成产生且内容一致，禁止人工分别维护。服务器继续读取原有扁平 JSON，现有发布接口和每天 09:00 的调度机制无需改变。

## 7. 自动校验

生成流程失败时不得覆盖现有运行文件。通过全部校验后，再以临时文件加原子替换的方式写入产物。

必须检查：

- 常规主题恰好 365 条；
- 365 个 `focus` 全部唯一；
- 每条有且仅有三项非空提醒和一句非空标语；
- 标题、提醒和标语满足海报长度上限；
- 不存在完全相同的提醒或完整文案；
- 通过分词或字符相似度发现高度相似条目，并输出人工复核报告；
- 各类别数量符合配额；
- 相同类别、对象和核心动作满足编排间隔；
- 不出现范围清单之外的设备、区域或作业关键词；
- 两份运行 JSON 的内容和校验摘要一致。

相似度检测只负责发现候选问题，不自动改写文案。人工判断两个主题是否存在实质差异后，再修改结构化源库。

## 8. 测试与人工审阅

现有测试中的主题数量从 120 改为 365，并保留同日选择稳定、次日不同、完整周期内标题不重复和周期结束后回到首条等行为测试。

移除“所有提醒必须以检查、严禁、注意、及时、确认开头”的限制，替换为以下验证：

- 内容非空、长度适配海报；
- 三条提醒不互相重复；
- 标题和完整文案唯一；
- 365 天编排间隔满足要求；
- 生成产物可被现有 Go 加载器正常解析。

上线前进行三层人工检查：

1. 每个安全类别随机抽查至少 5 条；
2. 连续查看任意 30 天，检查阅读节奏、相似度和现场相关性；
3. 选择长、中、短文案实际渲染海报，确认没有溢出、遮挡或不合理换行。

## 9. 部署与回退

部署前备份服务器现有主题库。上传新库后先在服务器执行解析和未来 30 天预览检查，确认数量、顺序和文案正常，再让现有每日 09:00 任务继续使用新库。

本次更新不补发历史内容，不更改群列表，不改变发布时间，也不修改已发送记录。部署失败或检查不通过时恢复备份文件并重启相关服务。

## 10. 非目标

本设计不包括：

- 天气查询或天气主题插播；
- 按季节、月份或节假日动态选题；
- 根据 AI 在发布当天实时生成文案；
- 质量、环保、企业文化等非安全内容；
- 修改海报视觉模板或每日发布时间；
- 为现场不存在的作业准备备用主题。
