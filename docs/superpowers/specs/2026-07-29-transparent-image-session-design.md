# 透明图片会话与模型直通设计

## 1. 背景与目标

当前图片请求由普通聊天 Agent 选择 Skill，再由聊天 Agent 选择执行脚本。这个流程会导致聊天模型改写用户提示词、为水印等任务补充未要求的样式，并且图片脚本还会把输出尺寸限制到少数固定档位。

本设计的目标是让微信机器人的图片体验接近 ChatGPT 网页端：

- 用户可以用自然语言描述任意生图或改图需求。
- 图片请求不经过普通聊天 Agent 的提示词改写和多轮 Skill 工具调用。
- 用户原始作图文字尽可能原样传给图片模型。
- 文生图不由机器人指定尺寸或画质。
- 改图优先沿用当前目标图的原始尺寸，不静默缩放到项目固定档位。
- 支持多图会话、目标图/参考图角色和连续编辑。
- 会话空闲五分钟自动结束，并在第四分钟主动提醒创建者。

本设计不承诺突破图片模型、上游中转服务、微信协议、内容安全或网络服务的客观限制。遇到这些限制时，机器人应报告真实错误，不偷偷改变用户请求。

## 2. 范围与非目标

### 范围

- 私聊和群聊的独立图片会话。
- 图片消息自动加入会话并编号。
- 引用图片、当前目标图和显式参考图片的传递。
- 文生图和图片编辑的直通调用。
- 原始提示词、输入映射、尺寸和错误的结构化日志。
- Redis 会话状态、滑动 TTL、第四分钟提醒和第五分钟过期。
- 主动引用图片编号的 Type 57 消息尝试及普通文本降级。
- FNOS Docker 部署所需的配置、协议验证和回归测试。

### 非目标

- 不新增水印、换背景、海报等固定关键词列表。
- 不把 Pillow、ImageMagick 或其他本地图像处理工具作为图片请求的必经路由。
- 不用本地工具替代生成式模型的语义编辑、扩图、风格迁移或内容生成。
- 不删除现有普通聊天、知识库、业务路由和图片自动上传能力。
- 不改变微信消息历史和现有 OSS 保留策略。

## 3. 用户体验

### 3.1 创建会话

以下事件自动创建或刷新图片会话：

1. 用户发送图片消息。
2. 用户引用图片发送文字。
3. 在已有图片会话中发送任何作图文字。

图片消息进入会话后，第一张图片编号为 `图1 · 目标图`，后续图片默认编号为 `图2 · 参考图`、`图3 · 参考图`。机器人主动引用刚收到的图片回复编号；如果协议服务不支持 Type 57 引用消息，则发送普通文字编号作为降级。

纯文字且当前没有图片会话时，机器人需要在普通聊天和图片请求之间路由。路由器只返回 `chat` 或 `image`，不得生成回复、改写提示词或添加图片要求。路由器只调用一次；一旦进入图片会话，后续图片会话文字不再调用聊天 Agent。

### 3.2 直通提示词

机器人只移除通信层内容，例如机器人艾特和配置的触发前缀。其余用户文字作为 `raw_prompt` 保存，并作为图片请求的用户提示词传递。禁止自动添加负面提示词、尺寸描述、画质、风格、构图、重复水印、保真要求或“其他内容保持不变”等未由用户提出的内容。

多图输入只附带必要的内部输入映射，例如目标图对应 `图1`、参考图对应 `图2`。映射用于保证模型知道附件顺序，不改变用户的语义指令。

### 3.3 文生图

没有目标图时调用图片生成接口：

- 不发送 `size`，由模型默认策略决定输出尺寸。
- 不发送 `quality`，由模型默认策略决定画质。
- 不对返回图片做二次裁剪、缩放或质量等级转换。

### 3.4 图片编辑

有目标图时调用图片编辑接口：

- 目标图为当前会话目标，明确引用图片时引用优先。
- 如果目标图尺寸符合所选模型和上游服务约束，传入目标图原始宽高。
- 不强制三档尺寸，不静默改成方图、横图或竖图。
- 不强制 `quality`。
- 如果原始尺寸被模型或中转服务拒绝，返回明确错误；是否允许用户重试由用户下一条指令决定。

模型可能重绘原图内容，这是生成式编辑的固有行为。需要像素级不变的水印、裁剪、压缩等操作不在本设计中自动切换到本地工具。

生成成功后，输出消息加入会话并成为新的当前目标图；参考图角色不自动替换。

### 3.5 多图和连续编辑

会话状态保存素材编号、消息 ID、角色和当前目标。用户可以在自然语言中引用编号，例如：

```text
以图1为目标，参考图2的配色，把图3的商品替换进去
```

用户可以发送 `图2设为目标图`、`删除图3`、`查看素材` 等会话管理请求；这些是会话控制 API，不是生图提示词规则。图片模型只接收当前请求明确需要的目标和参考素材，避免旧图隐式污染新任务。

## 4. 会话数据模型与生命周期

会话键由以下字段组成并进行稳定编码：

```text
robot_id + conversation_id + sender_wxid
```

其中私聊 `conversation_id` 为对方微信 ID，群聊为群 ID，`sender_wxid` 始终为会话创建者。Redis 只保存元数据，不保存图片二进制：

```json
{
  "session_id": "img_xxx",
  "created_by": "wxid_xxx",
  "next_number": 4,
  "target": 1,
  "last_output": 0,
  "warning_sent": false,
  "state": "idle",
  "assets": [
    {"number": 1, "message_id": 1287, "role": "target"},
    {"number": 2, "message_id": 1290, "role": "reference"}
  ]
}
```

会话默认空闲 TTL 为五分钟。添加图片、角色变更、开始图片任务、发送成功、任务失败和用户继续操作都会刷新 TTL，并将 `warning_sent` 置为 false。`processing` 状态下禁止空闲提醒和过期删除；任务结束后恢复五分钟空闲 TTL。

第四分钟提醒由持久化调度任务扫描 Redis 中的会话元数据和最后活动时间完成，而不是只依赖进程内计时器。提醒通过原会话发送：群聊艾特 `created_by`，私聊直接发送。提醒发送使用幂等标记，重启或重复扫描不会重复提醒。第五分钟由 Redis TTL 清理会话，后台清理器删除该任务关联的临时下载文件。

任务超时、服务重启或清理失败不能删除微信历史记录和 OSS 资源；临时文件清理必须是可重试的，并记录失败路径。

## 5. 组件与数据流

### 5.1 ImageSessionPlugin

新增图片会话插件，注册在普通群聊/私聊 AI 插件之前：

- 图片消息：写入素材、刷新 TTL、主动编号回复，并标记消息已处理。
- 引用图片文字：解析引用目标，写入/绑定目标后直通图片服务。
- 已有会话文字：解析会话控制或直接作为图片提示词。
- 无会话纯文字：调用一次只做路由的分类器；`image` 进入图片流程，`chat` 放行原普通聊天插件。

插件必须设置 `ctx.Handled`，避免同一条图片请求继续进入普通聊天 Agent。

### 5.2 ImageSessionService

服务层负责 Redis 原子读改写、素材编号、目标/参考角色、TTL 刷新、并发版本和过期提醒状态。并发更新使用分布式锁或 Redis CAS，避免同一用户连续发送图片时编号重复、目标回退或提醒标记丢失。

### 5.3 DirectImageService

服务层负责调用现有图片脚本或抽取出的图片 API 适配器。适配器接口接收：

- 未修改的 `raw_prompt`。
- 目标消息 ID和参考消息 ID列表。
- 可选的目标原图宽高。
- 模型和上游配置。

适配器不负责决定用户意图，不调用普通聊天 Agent，不生成补充提示词。下载的输入文件只在任务生命周期内存在，任务结束后立即清理。

### 5.4 QuoteMessageBuilder

新增引用消息 XML 构造辅助函数，使用现有 `MessageService.SendAppMessage` 和 `AppMsgTypequote=57`。消息 XML 必须包含被引用消息所需的 `refermsg` 字段。该能力先在 FNOS 协议服务上验证私聊、群聊和艾特渲染；协议失败时调用普通文本发送降级。

### 5.5 SessionExpiryWorker

新增后台周期任务，每次扫描即将达到四分钟空闲时间的会话，发送一次提醒；Redis TTL负责最终删除。任务执行和消息发送必须可重入，不能因为提醒失败而延长会话或阻止后续清理。

## 6. 现有实现的迁移边界

- `AIChatPlugin` 保留普通聊天能力，但不再处理已进入图片会话的图片请求。
- `activate_skill`、`execute_skill_script` 保留给其他 Agent 场景；图片会话不经过它们。
- 旧的最近图片时间窗口和 `reference_count` 自动查找不能继续作为图片会话的素材来源；改为会话中显式的消息 ID列表。
- 现有图片脚本的固定尺寸桶、自动负面提示词和编辑提示词拼接逻辑需要移除或改为透明参数传递。
- 现有图片自动上传插件继续独立运行；图片会话不得依赖 OSS 自动上传是否开启。
- 旧图片上下文设计文档保留作为历史记录，新实现以本设计为准。

## 7. 错误、并发与安全

- 上游暂时不可用：向用户返回可理解的失败消息，并保留会话和素材；仅对明确可重试的网络错误进行有限重试。
- 参数或尺寸不受支持：返回实际错误，不降级成固定尺寸。
- 输入图片下载失败：不启动模型请求，保留素材元数据并提示重试。
- 同一会话同时只能有一个图片任务；后续消息可排队或返回“上一任务处理中”，不能覆盖当前目标。
- Redis 不可用：不创建可丢失的图片会话；普通聊天继续按现有行为运行并记录错误。
- 所有用户提供的提示词只作为请求数据，不拼接为 shell 命令；若保留脚本执行，必须使用结构化参数和严格的临时文件清理。
- 下载和返回图片需限制文件大小、响应超时和临时目录范围，防止异常资源消耗。

## 8. 测试和验收

### 单元测试

- 会话键在私聊、群聊和不同发送者之间隔离。
- 素材编号、目标切换、删除和输出升级目标正确。
- TTL刷新、第四分钟只提醒一次、第五分钟过期。
- `processing` 状态不会被提醒或清理。
- 通信字段移除后用户原始提示词保持不变。
- 文生图请求不包含 `size`、`quality`；改图只在原尺寸合法时传原尺寸。
- 图片会话请求不会进入普通聊天 Agent。
- 普通聊天仍能放行到原 AI 插件。
- Type 57 XML字段构造和普通文本降级。

### 集成测试

- 纯文字生图、单图改图和多图参考图。
- 私聊和群聊中的主动图片编号与第四分钟艾特提醒。
- 模型生成超过五分钟时的会话生命周期。
- 上游失败、超时和非法尺寸的用户提示。
- FNOS 协议服务的 Type 57 私聊/群聊引用效果。

### FNOS 验收

在 N100 小主机部署候选镜像后，使用真实微信账号验证：原始提示词日志、原图尺寸传递、模型返回尺寸、引用编号、艾特提醒和临时文件清理。Mac 本地源码变更不会自动影响 FNOS，部署必须通过镜像或二进制更新完成。

## 9. 可观测性

每个图片任务使用 `session_id` 和 `request_id` 关联以下日志：

```text
raw_prompt
sanitized_prompt
target_message_id
reference_message_ids
model
requested_size
returned_size
elapsed
upstream_error
```

日志不得记录 API 密钥。成功和失败都应记录会话状态变化，便于比较“图一/图五”这类尺寸和内容差异。
